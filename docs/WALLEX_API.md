# راهنمای جامع تعامل با رابط برنامه‌نویسی والکس (Wallex API Reference)

این سند مرجع فنی قطعی و تست‌شده جهت برقراری ارتباط پایدار، استعلام داده‌های عمومی و ارسال ایمن سفارش‌ها به صرافی والکس است.

---

## ۱. مشخصات عمومی و آدرس پایگاه
- **آدرس پایه (Base URL):** `https://api.wallex.ir`
- **فرمت تبادل داده:** JSON (`Content-Type: application/json`)
- **شیوه احراز هویت اندپوینت‌های خصوصی:** هدر `x-api-key: YOUR_API_KEY`
- **منطقه زمانی سرور:** `Asia/Tehran`

---

## ۲. اندپوینت‌های عمومی (Public Endpoints)

### ۲.۱. فهرست بازارها و متادیتا (Markets Metadata)
- **مسیر:** `GET /v1/markets`
- **احراز هویت:** بدون نیاز به توکن (عمومی)
- **توضیح:** این اندپوینت اطلاعات کامل تمام ۳۷۳ نماد صرافی، دارایی پایه، دارایی مظنه، تعداد ارقام اعشار (`stepSize`, `tickSize`)، حداقل حجم (`minQty`)، حداقل ارزش سفارش به تومان (`minNotional = 50,000 TMN`) و آمار ۲۴ ساعته (حجم معاملات، قیمت آخرین معامله، بالاترین/پایین‌ترین) را بازمی‌گرداند.

### ۲.۲. دفتر سفارش و عمق بازار (Order Book Depth)
- **مسیر:** `GET /v1/depth?symbol={symbol}`
- **پارامترها:** `symbol` (مثال: `BTCTMN` یا `ETHTMN`)
- **ساختار پاسخ:**
```json
{
  "result": {
    "ask": [{"price": 22239999983, "quantity": 0.0044964, "sum": "99999935.92"}],
    "bid": [{"price": 22208403251, "quantity": 0.0631267, "sum": "1401948835.3"}]
  }
}
```
- **کاربرد:** محاسبه دقیق اسپرد (Spread) و تخمین اسلیپیج قبل از هر معامله.

### ۲.۳. آخرین معاملات انجام‌شده (Recent Trades)
- **مسیر:** `GET /v1/trades?symbol={symbol}`
- **توضیح:** لیست آخرین معاملات نهایی‌شده به همراه حجم، قیمت و جهت معامله (`isBuyOrder`).

### ۲.۴. دریافت داده‌های کندل تاریخی (TradingView UDF History)
- **مسیر:** `GET /v1/udf/history?symbol={symbol}&resolution={res}&from={from_timestamp}&to={to_timestamp}`
- **پارامترها:**
  - `symbol`: نماد بازار (مثال: `BTCTMN`)
  - `resolution`: تایم‌فریم کندل‌ها (`1`, `15`, `60`, `240`, `480`, `720`, `D`)
  - `from`: تایم‌استمپ یونیکس شروع
  - `to`: تایم‌استمپ یونیکس پایان
- **ساختار پاسخ:**
```json
{
  "s": "ok",
  "t": [1700002800, 1700006400],
  "o": ["1825000000", "1826000000"],
  "h": ["1829000000", "1831000000"],
  "l": ["1824000000", "1825000000"],
  "c": ["1828210944", "1830000000"],
  "v": ["1.245", "0.854"]
}
```

## ۳. اندپوینت‌های خصوصی و مدیریت سفارش‌ها (Private Endpoints)

### ۳.۱. استعلام موجودی کیف پول (Account Balances)
- **مسیر:** `GET /v1/account/balances`
- **هدر:** `x-api-key: YOUR_KEY`
- **پاسخ:** مقادیر موجودی نقدی (`value`) و مقدار قفل‌شده در سفارش‌های باز (`locked`) به تفکیک دارایی‌ها.

### ۳.۲. ثبت سفارش جدید (Place Order)
- **مسیر:** `POST /v1/account/orders`
- **هدرها:**
  - `Content-Type: application/json`
  - `x-api-key: YOUR_KEY`
- **بدنه درخواست (JSON):**
```json
{
  "symbol": "BTCTMN",
  "type": "LIMIT",
  "side": "BUY",
  "price": "22200000000",
  "quantity": "0.0000225"
}
```
- **انواع سفارش مجاز:** `LIMIT`, `MARKET` (سفارش‌های محدود `LIMIT` برای کنترل ریسک لغزش الزامی هستند).

### ۳.۳. استعلام سفارش‌های باز (Open Orders)
- **مسیر:** `GET /v1/account/open-orders`
- **کاربرد:** نظارت بر وضعیت پر شدن، لغو سفارش‌های منقضی‌شده و جلوگیری از قفل ماندن سرمایه.

### ۳.۴. لغو سفارش فعال (Cancel Order)
- **مسیر:** `DELETE /v1/account/orders?clientOrderId={id}` یا `orderId={id}`
- **کاربرد:** لغو فوری سفارش در صورت تغییر روند بازار یا فرا رسیدن مهلت زمانی (Timeout).

---

## ۴. مدیریت خطاها و کدهای وضعیت متداول (Error Handling)
- `1201`: هدر احراز هویت نامعتبر یا کلید API اشتباه است.
- `422`: عدم تطابق پارامترها (مانند مقدار کمتر از `minNotional` یا خطای اعشار).
- `429`: محدودیت نرخ ارسال درخواست (Rate limit exceeded) - سیستم باید بک‌آف نمایی (Exponential Backoff) اعمال کند.
- `5xx`: خطای موقت سرور والکس یا شبکه اینترنت - سیستم باید تراکنش را بررسی مجدد نموده و بدون تایید وضعیت از ارسال سفارش تکراری خودداری کند.
